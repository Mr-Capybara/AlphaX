# Alpha因子自动化挖掘方法探索

## 1.目标定位

+ 本项目是一个技术探索项目，目标是研究和改进公式化 Alpha 因子的自动化挖掘方法，并产出一篇论文，作为本科毕业设计。

methods目录下，存放了若干已有开源工作，作为复现、对比和方法改进的基础。

+ 理想路径是：
1.复现已有的各种代表性方法。在统一的 A 股日频量价数据和评价口径下比较其样本外预测表现，从实验结果中识别有改进空间的环节。
2.提出并验证新的方法。研究力争在相同实验条件下超过最强的已复现基线，并用对照实验说明提升来自哪些改动。
3.根据有效改动，包装出一个自己的idea，产出一篇学术论文。

## 2.仓库结构

+ methods目录下，有若干子目录，分别是已有的不同Alpha因子自动化挖掘方法（AlphaX）以及待产出的自己的方法（Ours）。
+ 因为该项目具有较强的探索性，所以可能周期较长，单个对话无法完成，必须在工作区中维护一套面向后续 Codex 和人类协作者的项目文档。
    + doc-to-user/ 是给人类看的，帮助其理解项目
    + doc-to-agent/ 是给后续 Codex / agent 协作者看的，作为执行交接文档，以便于其快速理解项目状态，上手工作

## 3.文档规范
主要介绍 doc-to-agent/ 目录的相关规范，需要**严格遵守**
+ `CONVENTIONS.md`：开发与协作规范
+ `PLAN.md`：阶段计划，只能在人类讨论后，得到确认后写入或调整
+ `STATUS.md`：当前执行状态，说明 PLAN 已完成到哪一步，主要由 agent 更新
+ `TODO.md`：下一步行动，对应 PLAN 中尚未完成的某一步，主要由 agent 更新
+ `DECISIONS.md`：技术决策记录，只记录迭代中已经形成的明确决策
+ `EXPERIMENTS.md`：实验记录和实验索引，不写大段原始日志
+ `HISTORY.md`：归档已经落地完成的 PLAN
